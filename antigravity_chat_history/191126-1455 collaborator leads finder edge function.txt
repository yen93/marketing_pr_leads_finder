1. ARCHITECTURE & PROJECT SCAFFOLDING
--------------------------------------------------------------------------------
* Problem / Context:
  Needed an automated weekly pipeline to discover at least 20 potential media,
  podcast, influencer, and social-media collaboration partners per week for
  James Castrission / My Adventure Group (AU/NZ + Global English focus, modeled
  after Diary of a CEO, BuzzFeed, and Agency Podcast while excluding
  agencypodcast since James already collaborated with them).

* Architectural Decision:
  - Selected a hybrid OpenAI Responses API (`web_search` + strict `json_schema`)
    plus direct website/contact-page and Apple iTunes/podcast RSS scraping stack.
  - Only requires `OPENAI_API_KEY` (already configured on MAGTestProject) and
    fits comfortably inside Supabase Edge Function execution limits.

* Project Files Created:
  - supabase/config.toml
  - package.json (Node 24 native TypeScript unit test runner)
  - .env.example
  - .gitignore (updated to ignore SUPABASE_ACCESS_TOKEN.txt)

* Iterative Refinements Across Versions (v1 -> v4):
  - v2: Added Apple Podcasts numeric ID extraction (`extractApplePodcastId`) +
    `https://itunes.apple.com/lookup?id=...` exact RSS lookup; strengthened prompt
    against guessing generic `info@` emails.
  - v3: Enforced 100% verified-only email policy—only emails directly scraped
    from official podcast RSS feeds (`rss_feed`) or official brand websites/contact
    pages (`website_scrape`) are saved; unverified AI emails are discarded and
    the lead is saved POC-only (`email = NULL`). Added `isDirectoryOrSocialUrl`
    guard to avoid scraping third-party directory footer emails.
  - v4: Fixed OpenAI Responses API JSON truncation observed on live run #1
    ("Unterminated string in JSON" when requesting 16 candidates per call) by
    setting `max_output_tokens: 4500`, reducing per-batch request size to 6-8
    candidates, increasing default `max_batches` to 6, selecting the final
    assistant message block, adding `parseCandidatesJson` truncated-JSON salvage,
    and strengthening named-POC prompting.
